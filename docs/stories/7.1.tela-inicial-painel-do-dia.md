## Story
**As a** jogador que usa o TibiaHunt,
**I want** ver as informações do dia no Tibia (boss boostado, criatura boostada, cidade do Rashid) assim que eu logar, com atalhos pras outras telas do app,
**so that** eu tenha um ponto de partida útil em vez de cair direto numa lista de hunts, e já saiba se vale a pena caçar o boss/criatura boostados hoje.

## Acceptance Criteria
1. Given o usuário loga, When a tela carrega, Then a aba "Início" é a view padrão (substitui "Minhas Hunts" como padrão — a aba "Minhas Hunts" continua existindo, só deixa de ser a primeira a aparecer).
2. Given a tela Início, When carregada, Then mostra o boss boostado do dia (nome + imagem), buscado de `https://api.tibiadata.com/v4/boostablebosses` (campo `boostable_bosses.boosted`).
3. Given a tela Início, When carregada, Then mostra a criatura boostada do dia (nome + imagem), buscada de `https://api.tibiadata.com/v4/creatures` (campo `creatures.boosted`).
4. Given a tela Início, When carregada, Then mostra a cidade do Rashid hoje, calculada localmente a partir do dia da semana atual (tabela fixa, sem chamada de API): Segunda-Svargrond, Terça-Liberty Bay, Quarta-Port Hope, Quinta-Ankrahmun, Sexta-Darashia, Sábado-Edron, Domingo-Carlin.
5. Given a busca do boss e/ou da criatura boostados falhar (TibiaData API fora do ar), When isso acontece, Then a tela não quebra — a localização do Rashid e os cards de navegação continuam aparecendo normalmente, com uma mensagem discreta indicando que os boosts não puderam ser carregados agora.
6. Given a tela Início, When carregada, Then mostra 5 cards clicáveis, um pra cada aba existente (Minhas Hunts, Hunts Compartilhadas, Meu Profit, Metas, Configurações) — clicar em um navega pra aquela aba.

## Complexity
T-shirt size: **S** — 2 funções novas em `tibiaDataClient.js` (reaproveitando o padrão já existente de `fetchCharacter`), 1 util estático (Rashid), 1 página nova, sem migration.

## Business Value
Dá ao app uma porta de entrada com valor imediato (informação do dia + navegação), em vez do usuário cair direto numa lista de hunts que pode estar vazia. Também é a forma mais simples de expor uma informação da TibiaData API que hoje não é usada em lugar nenhum (boosts).

## Risks
- **Fuso horário na virada do dia:** calcular o dia da semana pelo horário local do navegador pode divergir por algumas horas do server save real do Tibia (10:00 CET) perto da meia-noite. Aceito como aproximação de MVP — não é um bug a resolver agora, só uma imprecisão de poucas horas numa janela específica do dia.
- **TibiaData fora do ar:** coberto pelo AC 5 — degradação graciosa, mesmo padrão já usado no resto do projeto (Story 2.2).

## Dev Notes

**Contexto:**
- `src/lib/tibiaDataClient.js` já expõe `fetchCharacter`, `TibiaDataUnavailableError`, `CharacterNotFoundError`, `fetchHighscorePage` — seguir exatamente o mesmo estilo (classes de erro, `BASE_URL`, tratamento de status HTTP) pras 2 funções novas.
- **Confirmado nesta sessão, ao vivo, direto do browser (sem RPC, sem CORS):**
  - `GET https://api.tibiadata.com/v4/boostablebosses` → `{ boostable_bosses: { boosted: { name, image_url, featured }, boostable_boss_list: [...] } }`
  - `GET https://api.tibiadata.com/v4/creatures` → `{ creatures: { boosted: { name, race, image_url, featured }, creature_list: [...] } }`
  - Diferente do endpoint `/creature/{name}` (Epic 4, migrations 016-022), que precisou de RPC server-side por causa de CORS — aqui **não é necessário**, é client-side puro, igual `fetchCharacter`.
- Nav atual do `App.jsx` usa chaves de view: `'dashboard'` (Minhas Hunts), `'feed'` (Hunts Compartilhadas), `'profit'` (Meu Profit), `'metas'` (Metas — adicionado no Epic 6), `'settings'` (Configurações). A nova view é `'home'`.
- Rashid: tabela fixa, **não é dado de API** — hardcoded no util, com o dia da semana como chave.

**Fora de escopo:**
- Cache de boss/criatura boostados (ex.: localStorage por dia) — não é necessário pro MVP, os endpoints são leves e chamados só 1x ao carregar a tela Início.
- Ajuste de fuso horário preciso pro server save do Tibia — ver Riscos.
