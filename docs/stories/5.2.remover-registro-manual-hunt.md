## Story
**As a** dono do app,
**I want** que a única forma de registrar uma hunt seja colando o texto do Session Analyser,
**so that** todo dado registrado no TibiaHunt venha de uma fonte confiável (o próprio jogo), sem números digitados à mão que podem estar errados ou inflados.

## Acceptance Criteria
1. Given a tela de registrar hunt (`SessionForm`), When carregada, Then existe só o campo de colar o texto do Session Analyser e o botão "Analisar" — nenhum botão ou caminho de UI leva a um formulário de preenchimento do zero.
2. Given um texto colado que o parser não reconhece, When o usuário clica em "Analisar", Then vê uma mensagem de erro clara ("Não consegui reconhecer esse texto. Confira se colou o conteúdo completo do Session Analyser e tente de novo.") — o texto colado continua no campo, editável, pra tentar de novo.
3. Given um texto colado reconhecido com sucesso, When o preview aparece, Then o usuário ainda pode editar os campos numéricos extraídos (XP Gain, Loot, Supplies, etc.) antes de salvar — esse comportamento já existente **não muda**.
4. Given o código depois desta story, When inspecionado, Then não existe mais nenhum estado, função ou campo relacionado ao preenchimento manual do zero (`manualFields`, `manualDuration`, `EMPTY_MANUAL_FIELDS`, `updateManualField`) — código morto removido, não só escondido.

## Complexity
T-shirt size: **S** — remoção de código existente + 1 ajuste de mensagem de erro, sem lógica nova, sem mudança de schema.

## Business Value
Fecha um requisito direto do usuário: nenhum dado no sistema deve vir de digitação manual — só do que o próprio Tibia gerou (Session Analyser).

## Risks
- **Sessões antigas com `source = 'manual'`:** continuam existindo e sendo exibidas normalmente em todo lugar do app — só o caminho de **criar** novas é removido. Sem migração de dados, sem alterar o `check` constraint de `sessions.source` (ele já aceita `'parsed'` e `'manual'`, e vai continuar aceitando ambos os valores já gravados).
- **Usuário com texto real que o parser não reconhece (bug no parser, formato novo do Tibia):** antes, ele tinha uma saída (preencher manual). Agora, se o parser falhar, ele fica travado até o parser ser corrigido. Mitigação: fora do escopo desta story consertar o parser — se isso acontecer na prática, vira um bug separado no `sessionParser.js`, não uma razão pra manter o modo manual.

## Dev Notes

**Contexto:**
- `SessionForm.jsx` hoje tem 3 modos (`paste`, `preview`, `manual`). O `manual` é acionado de 2 formas: clique direto no botão "Preencher manualmente" (`mode === 'paste'`), ou fallback automático quando `parseSessionText(rawText)` retorna `null` dentro de `handleAnalyze`. As duas entradas somem nesta story.
- `parseSessionText` (`src/lib/sessionParser.js`) não é tocado por esta story — só o que a UI faz quando ele retorna `null` muda (antes: cai no modo manual; agora: mostra erro e mantém no modo paste).
- `sessions.source` (schema base, `supabase/schema.sql`) tem `check (source in ('parsed', 'manual'))` — **não precisa mudar**, porque sessões antigas com `'manual'` continuam válidas e exibidas; só a UI que cria `source = 'manual'` novo deixa de existir.
- Nenhuma outra tela (`SessionList.jsx`, `HuntsFeed.jsx`, `HuntCard.jsx`, `Profit.jsx`) faz nenhuma distinção visual por `source` hoje — nada nelas precisa mudar.

**Fora de escopo:**
- Melhorar o `sessionParser.js` em si (robustez de parsing) — só a reação da UI a uma falha de parse muda.
- Qualquer alteração em sessões já salvas com `source = 'manual'`.

### Testing
- Testar colar um texto de Session Analyser real válido → preview aparece normalmente, editar um campo, salvar → funciona como antes.
- Testar colar um texto qualquer que não seja um Session Analyser (ex.: texto aleatório) → mensagem de erro aparece, texto continua no campo, nenhum formulário manual aparece em nenhum momento.
- Confirmar visualmente que não existe mais nenhum botão "Preencher manualmente" em lugar nenhum da tela.
