## Story
**As a** jogador com mais de um personagem (principal + makers),
**I want** gerenciar todos os meus personagens — cadastrar, verificar, sincronizar stats e remover — em uma tela de Configurações dedicada, escolhendo o tipo de cada um ao cadastrar,
**so that** eu tenha um único lugar previsível pra administrar personagens, e a tela de Hunts (Story 3.3) fique livre de qualquer cadastro.

## Acceptance Criteria
1. Given a navegação do app, When usuário clica na nova aba "Configurações", Then vê a lista de personagens já cadastrados (nome, mundo, tipo, verificação, stats) e o formulário de cadastro — reaproveitando `CharacterList`/`CharacterForm`/`CharacterVerification`/`CharacterStats` já existentes, apenas realocados para essa tela.
2. Given o formulário de cadastro em Configurações, When usuário cadastra um personagem, Then escolhe o tipo — "Principal" ou "Maker" (default "Principal") — além de nome e mundo.
3. Given um personagem cadastrado com tipo "Maker", When exibido na lista em Configurações, Then mostra um badge "Maker" (e "Principal" para os demais, incluindo os já existentes antes desta story).
4. Given a migration de banco aplicada, When personagens criados antes desta story são listados, Then aparecem com tipo "Principal" (default da coluna), sem erro e sem exigir edição manual.
5. Given a policy de RLS existente (`Users manage own characters`, baseada em `user_id = auth.uid()`), When a coluna `type` é adicionada, Then a policy continua funcionando sem alteração (não depende da nova coluna).
6. Given a tela "Minhas Hunts" (Dashboard), When carregada após esta story, Then não existe mais nenhum formulário de cadastro/remoção de personagem nela — a seção "Personagens" inteira sai do Dashboard (o seletor de personagem ativo para registrar sessão continua funcionando até a Story 3.3 redesenhar essa tela por completo).

## Complexity
T-shirt size: **M** — migration simples + realocação de componentes já existentes entre telas + 1 componente novo (nav tab / página Settings). Sem lógica nova de negócio.

## Business Value
Pré-requisito de todas as outras stories do Epic 3 — Story 3.2 (ajustes de conta) usa a mesma tela de Configurações, e Story 3.3 (Hunts simplificada) depende do cadastro de personagem já não estar mais na tela de Hunts.

## Risks
- **Migration quebrar leitura de personagens existentes:** mitigado com `default 'principal'` na coluna nova + `check` constraint só validando `principal`/`maker` (sem `not null` sem default).
- **Perder o personagem ativo ao mover o CRUD:** `activeCharacterId` já é persistido em `localStorage` por `useCharacters` — como Dashboard e Configurações vão chamar o mesmo hook, a seleção continua consistente entre as duas telas sem precisar levantar estado pro `App.jsx`.

## Dev Notes

**Contexto (Epic 1, Story 1.1 e migrations 002-011):**
- Tabela `characters` (schema base em `supabase/schema.sql`): `id, user_id, name, world, created_at` + colunas de verificação/stats adicionadas nas migrations 002-011 (`verified`, `verification_code`, `stats_level`, `stats_vocation`, etc.). Nenhuma coluna de tipo existe ainda — é 100% nova nesta story.
- RLS de `characters` é só por `user_id = auth.uid()` (`supabase/schema.sql:60-63`) — adicionar coluna não exige nova policy.
- `useCharacters.js` já persiste `activeCharacterId` em `localStorage` (`ACTIVE_CHARACTER_KEY`), então Dashboard e a nova tela Configurações podem cada uma chamar `useCharacters()` independentemente sem perder sincronia da seleção ativa.
- `CharacterList.jsx` já usa `Badge` (`src/components/ui/Badge.jsx`) para o selo "✔ Verificado" — mesmo padrão a reutilizar pro badge de tipo.
- `App.jsx` hoje controla a view ativa com `useState('dashboard')` e renderização condicional simples (`view === 'dashboard' ? <Dashboard/> : <HuntsFeed/>`) — trocar para um `if/else if` de 3 branches (`dashboard` | `feed` | `settings`) é suficiente, sem precisar de router.

**Fora de escopo desta story (fica para as próximas):**
- Redesenho completo da tela Hunts (seletor de personagem + analyser + lista formatada) → Story 3.3.
- Renomear "Feed" para "Hunts Compartilhadas" e badge de autoria → Story 3.4.
- Ajustes de conta (trocar senha) dentro de Configurações → Story 3.2.
- Aba "Meu Profit" → Story 3.5.
