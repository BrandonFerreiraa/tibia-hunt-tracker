## Story
**As a** jogador de Tibia com um personagem cadastrado,
**I want** provar que sou o dono real do personagem via a TibiaData API,
**so that** meu perfil mostre dados reais confiáveis e ninguém mais possa reivindicar o mesmo personagem.

## Acceptance Criteria
1. Given o usuário clica em "Verificar personagem", When o sistema gera um código, Then esse código expira em 24h se não usado.
2. Given o código foi colado no campo "comment" do personagem em tibia.com, When o usuário clica em "Conferir", Then o backend consulta a TibiaData API e, se o comment contiver o código, marca `verified = true`.
3. Given um personagem já verificado por outra conta, When um segundo usuário tenta verificar o mesmo nome, Then a tentativa é bloqueada com mensagem clara (constraint única).
4. Given a TibiaData API está indisponível (502/503) no momento da conferência, When o usuário clica em "Conferir", Then vê uma mensagem de erro clara pedindo para tentar novamente mais tarde — sem crashar a página.

## Complexity
T-shirt size: **M** — integração com API externa + lógica de expiração/unicidade, mas sem UI complexa.

## Business Value
Base de confiança pro Epic 2 inteiro — sem verificação real, o feed de hunts (Story 2.3) e os stats (Story 2.2) não têm credibilidade.

## Risks
- **TibiaData API instável** (confirmado ao vivo durante o planejamento desta story: endpoint de character retornando 502/503) — mitigado por AC 4 (erro claro, sem crash) e possibilidade de tentar novamente.
- **Alguém tenta verificar personagem de outra pessoa** — mitigado por exigir escrita no comment (só o dono tem) + constraint única no nome do personagem.

## Dev Notes

**Contexto (Epic 2, Stories 1.1-1.4):**
- Tabela `characters` já existe (Story 1.1) — esta story só adiciona colunas, não recria a tabela.
- TibiaData API confirmada como fonte (PRD): `https://api.tibiadata.com/v4/character/{name}` retorna `comment` entre outros campos (`level`, `vocation`, `world`, `guild`, `achievement_points` — usados na Story 2.2).
- **Estado real observado ao planejar esta story:** o endpoint de character estava retornando 502/503 para qualquer nome testado, enquanto `/v4/worlds` respondia normalmente — ou seja, é uma instabilidade pontual da API, não um problema de integração. O código deve ser escrito para tolerar isso (AC 4) e testado de ponta a ponta contra a API real assim que ela normalizar.
- Constraint única em nome de personagem: usar `citext` ou `lower(name)` com índice único, já que nomes de personagem no Tibia não diferenciam maiúsculas/minúsculas de forma significativa para fins de unicidade.

### Testing
- Teste unitário do parser de resposta da API (`fetchCharacter`) pode ser feito com um JSON de exemplo mockado (sem depender da API estar de pé).
- Teste end-to-end (gerar código → colar no comment de um personagem real → conferir) depende da API estar disponível — pendente até a instabilidade atual passar.
- Teste de constraint única: tentar verificar o mesmo nome de personagem com 2 contas diferentes.

### Debug Log References
- **Vulnerabilidade real encontrada e corrigida durante o desenvolvimento:** o design original ("cliente confere e depois faz update") permitia que qualquer usuário chamasse `supabase.from('characters').update({verified:true})` direto do DevTools, sem nunca ter provado nada. Corrigido movendo a checagem pra uma função `SECURITY DEFINER` no Postgres (`verify_character`), que faz a chamada HTTP à TibiaData API ela mesma (via extensão `http`) e só ela pode gravar `verified = true`.
- **Bug real encontrado e corrigido:** a primeira versão do `revoke update (verified) ... from authenticated` não bloqueava nada, porque a role `authenticated` já tinha GRANT de UPDATE na tabela inteira (padrão do Supabase) — revoke de coluna não sobrepõe grant de tabela. Corrigido revogando o UPDATE geral e concedendo de volta só nas colunas que o cliente pode mesmo escrever (`migrations/004`).
- **Bug real encontrado e corrigido:** `http_get()` falhava com "Malformed input to a URL function" para nomes de personagem com espaço (comuns no Tibia). Corrigido com `urlencode()` da extensão `http` (`migrations/005`).
- **Confirmado ao vivo (não simulado):** a TibiaData API ficou fora do ar (502/503) durante todo o desenvolvimento desta story. Isso permitiu testar o AC 4 (degradação graciosa) contra uma falha real, não uma simulação.
