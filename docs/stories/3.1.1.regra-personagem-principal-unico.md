## Story
**As a** jogador com múltiplos personagens,
**I want** que só exista 1 personagem "Principal" por vez — e que marcar outro como Principal automaticamente rebaixe o anterior para Maker,
**so that** eu não acabe com vários personagens "Principal" ao mesmo tempo, o que não faz sentido pro conceito de conta principal + makers.

## Contexto
Achado durante teste manual da Story 3.1 (que tratava `type` como "só uma etiqueta, sem mudar comportamento" — decisão revisitada aqui pelo usuário). Personagens já cadastrados como Principal antes desta correção (ex.: Brandonlee, Issobra) **não são ajustados automaticamente** — o usuário corrige manualmente na tela de Configurações, usando a nova troca de tipo desta story.

## Acceptance Criteria
1. Given o usuário já tem um personagem Principal, When cadastra um novo personagem escolhendo "Principal" em Configurações, Then o personagem anterior é automaticamente rebaixado para "Maker" e o novo fica como "Principal" — sem erro, sem confirmação extra.
2. Given um personagem "Maker" já cadastrado, When o usuário clica no badge dele para marcá-lo como "Principal", Then esse personagem vira Principal e o Principal anterior (se existir) vira Maker automaticamente.
3. Given um personagem "Principal", When o usuário clica no badge para marcá-lo como "Maker", Then ele vira Maker diretamente, sem efeito colateral em outros personagens (pode temporariamente ficar sem nenhum Principal — permitido).
4. Given a lista de personagens em Configurações, When exibida, Then o badge de tipo é clicável e indica visualmente a ação (ex.: "Principal — clique p/ tornar Maker").
5. Given um Principal e pelo menos 1 Maker cadastrados, When o usuário remove o Principal, Then o Maker mais antigo (por `created_at`) é promovido a Principal automaticamente.
6. Given o usuário remove um personagem que não é Principal, When a remoção acontece, Then nenhum outro personagem tem seu tipo alterado.
7. Given o usuário remove o único personagem cadastrado (seja ele Principal ou não), When a lista fica vazia, Then nenhuma promoção é tentada (sem erro).

## Dev Notes
Regra aplicada só em nível de aplicação (não constraint de banco) — mais simples que um unique index parcial no Postgres para o volume de dados deste projeto, e consistente com a decisão do usuário de corrigir dados existentes manualmente em vez de via migration.
