## Story
**As a** usuário logado,
**I want** trocar a senha da minha conta direto na tela de Configurações,
**so that** eu não precise usar o fluxo de "esqueci minha senha" só pra atualizar a senha por vontade própria.

## Acceptance Criteria
1. Given a aba Configurações, When a tela carrega, Then existe uma seção "Conta" com um formulário de troca de senha (nova senha + confirmação), separada da seção "Personagens".
2. Given o usuário informa nova senha e confirmação iguais, com pelo menos 6 caracteres (mínimo já usado no cadastro, `Login.jsx`), When envia o formulário, Then `supabase.auth.updateUser({ password })` é chamado, a senha é atualizada e uma mensagem de sucesso é exibida, com os campos limpos.
3. Given a confirmação de senha diferente da nova senha, When o usuário tenta enviar, Then o formulário bloqueia o envio com mensagem de erro clara, sem chamar a API.
4. Given a nova senha com menos de 6 caracteres, When o usuário tenta enviar, Then o formulário bloqueia o envio com mensagem de erro, sem chamar a API (mesma validação client-side já usada no cadastro).
5. Given a API do Supabase retorna erro (ex.: mesma senha atual, sessão expirada), When o envio falha, Then a mensagem de erro da API (`error.message`) é exibida ao usuário sem quebrar a tela.

## Complexity
T-shirt size: **S** — 1 método novo no `AuthContext`, 1 componente de formulário novo, reaproveitando padrão visual já usado em `Login.jsx`.

## Business Value
Fecha a Story 3.1 (Configurações) com a segunda metade do escopo original — hoje não existe nenhuma forma de trocar senha dentro do app, só via fluxo de recuperação de senha do Supabase (fora do app).

## Risks
- **Sessão expirar no meio da troca:** `supabase.auth.updateUser` retorna erro nesse caso, capturado pelo AC 5 — sem tratamento especial adicional necessário.
- **Confusão entre "senha atual" e "nova senha":** o Supabase Auth não exige a senha atual pra trocar (usa a sessão já autenticada) — não pedir "senha atual" no formulário evita confusão com um campo que não existe no fluxo do Supabase.

## Dev Notes

**Contexto:**
- `AuthContext.jsx` hoje só expõe `signUp`, `signIn`, `signOut` — nenhum método de troca de senha existe ainda.
- `Login.jsx` já estabelece o padrão de validação de senha (`minLength={6}` no input, mesmo mínimo do Supabase Auth) e o padrão visual de erro/sucesso (`text-danger` / `text-success`) — reaproveitar exatamente esse padrão aqui, sem inventar um novo.
- Supabase Auth `updateUser({ password })` **não pede a senha atual** — a operação usa a sessão já autenticada do usuário. Por isso o formulário desta story não tem campo de "senha atual" (ver Risks).
- `Settings.jsx` (criada na Story 3.1) hoje só tem a seção "Personagens" — esta story adiciona a segunda seção ("Conta") na mesma página, sem criar uma aba nova.

**Fora de escopo:**
- Troca de email — não pedido, não incluído.
- Exigir "senha atual" — Supabase Auth não suporta esse fluxo nativamente sem reautenticação adicional; fora de escopo.

### Testing
- Testar manualmente: trocar a senha da conta real, deslogar, logar de novo com a nova senha pra confirmar que funcionou de ponta a ponta.
- Testar confirmação diferente → erro sem chamar API (nenhuma request de rede disparada).
- Testar senha com menos de 6 caracteres → erro client-side.
