## Story
**As a** jogador de Tibia usando o Hunt Tracker,
**I want** ver um feed público com as hunts que outros jogadores compartilharam,
**so that** eu possa comparar meu desempenho com o de outras pessoas.

## Acceptance Criteria
1. Given uma sessão recém-salva, When o usuário não altera nada, Then `is_shared = true` por padrão.
2. Given o usuário marca uma sessão sua como privada, When outro usuário acessa o feed, Then essa sessão não aparece — nem o personagem dela, nem a hunt.
3. Given o feed carregado, When não há nenhuma sessão compartilhada ainda, Then mostra mensagem clara de feed vazio (sem erro).
4. Given uma sessão de um personagem verificado aparece no feed, When exibida, Then mostra level/vocação reais junto (não dados que o usuário digitou manualmente).

**Fora de escopo desta story (fica pra Story 2.4):** filtros por monstro/mundo/vocação e ordenação — aqui o feed só lista por data (mais recente primeiro), sem filtros.

## Complexity
T-shirt size: **M** — schema simples (1 coluna + 1 view), mas exige navegação nova (2 telas) e cuidado de segurança (não vazar dados privados de outros usuários).

## Business Value
É o coração social do Epic 2 — sem isso, a verificação (2.1) e os stats (2.2) não têm pra onde "aparecer" publicamente.

## Risks
- **Vazamento de dados sensíveis de outros usuários** (ex: `verification_code`, `user_id`) via join direto nas tabelas — mitigado com uma **view dedicada** (`public_hunts_feed`) que expõe só os campos públicos, em vez de abrir RLS geral nas tabelas `sessions`/`characters`.
- **Usuário surpreendido pelo padrão "compartilhado"** — mitigado com texto explicativo perto do toggle de privacidade.

## Dev Notes

**Contexto (Stories 1.1-2.2):**
- `sessions` já tem RLS "owner-only" (Story 1.1) — **não mexer nela**. A view pública contorna isso de propósito (roda com o dono da view, não do usuário), então filtra explicitamente `where is_shared = true` na própria definição da view, não dependendo de RLS pra segurança.
- `characters` tem colunas sensíveis (`verification_code`, `user_id`) que **nunca** devem aparecer na view pública — só selecionar campos explicitamente seguros.
- Padrão de "top monstros": subquery com `string_agg` limitado a 3, ordenado por quantidade — evita ter que criar view pública separada pra `session_monsters`.
- Sem `react-router` no projeto ainda — introduzir só se realmente necessário; 2 telas dá pra resolver com estado local em `App.jsx` (mesmo padrão usado pra alternar Login/Dashboard).

### Testing
- Teste de segurança (mesmo padrão dos scripts `dev-test-*`): 2 contas, uma marca sessão como privada, confirmar que a outra conta NÃO vê essa sessão no feed nem os dados do personagem dela.
- Teste manual: sessão real já existente ("War do Rift", Story 1.3) deve aparecer no feed por padrão (is_shared=true), com dados do personagem "Brandonlee" se ele estiver vinculado e verificado.
