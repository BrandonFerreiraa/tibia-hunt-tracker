## Story
**As a** jogador de Tibia,
**I want** poder cancelar minha meta ativa sem precisar criar uma nova no mesmo fluxo,
**so that** eu consiga desfazer um erro de digitação (data ou valor errado) sem isso virar um resultado "Não batida" falso no meu histórico.

## Acceptance Criteria
1. Given uma meta `active`, When o usuário clica em "Cancelar meta" e confirma, Then a meta passa pra `status: 'cancelled'` e some do painel de progresso, sem exigir os campos de uma meta nova.
2. Given uma meta `cancelled` no histórico, When exibida, Then aparece com um resultado neutro (badge "Cancelada"), nunca como "Não batida" — evita confundir uma meta abandonada por engano com uma meta perdida de verdade.
3. Given nenhuma meta `active`, When o usuário acessa a página, Then não vê o botão "Cancelar meta" (só aparece quando há meta pra cancelar).

## Complexity
T-shirt size: **S** — 1 migration mínima (amplia um `check` constraint existente), 1 função nova no hook já existente, 1 botão + confirmação na UI já existente. Nenhuma tabela nova, nenhum componente novo.

## Business Value
Fecha uma lacuna real encontrada pelo usuário depois de testar o fluxo de meta (Story 6.3): hoje a única forma de "desistir" de uma meta é criar outra, o que grava um resultado enganoso no histórico.

## Risks
- **Nome do constraint incorreto na migration:** o Postgres nomeia constraints `check` inline automaticamente como `{tabela}_{coluna}_check` quando não nomeados explicitamente (`goals_status_check` — foi assim que a Story 6.1 criou, sem nome explícito). **Mitigação:** `@dev`/`@data-engineer` deve confirmar o nome real do constraint no banco (`\d goals` no SQL Editor, ou `select conname from pg_constraint where conrelid = 'goals'::regclass`) antes de rodar o `alter table ... drop constraint`, já que não há acesso a essa confirmação nesta story (schema só documentado, não consultado ao vivo).
- **`GoalHistory` mostrar "Resultado final: 0kk" pra uma meta cancelada** (já que `final_profit_gold` fica `null`/não setado): daria a entender que a pessoa fez 0 de profit, quando na verdade a meta só foi abandonada. **Mitigação:** tratar `status === 'cancelled'` como um caso à parte na renderização do histórico, sem mostrar a linha de "Resultado final".
