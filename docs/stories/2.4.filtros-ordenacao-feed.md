## Story
**As a** jogador navegando pelo feed de hunts compartilhadas,
**I want** filtrar por monstro, mundo, vocação e período, e ordenar por data/profit/XP,
**so that** eu consiga achar rápido as hunts relevantes pra mim, em vez de rolar uma lista genérica.

## Acceptance Criteria
1. Given o feed carregado, When aplico um filtro de monstro (texto livre), Then só vejo hunts onde esse monstro apareceu na sessão (não só nos "top 3" exibidos no card).
2. Given o feed carregado, When aplico um filtro de mundo, Then só vejo hunts daquele mundo.
3. Given o feed carregado, When aplico um filtro de vocação, Then só vejo hunts de personagens verificados com aquela vocação (personagens não verificados não têm vocação conhecida, então são excluídos ao filtrar por vocação — comportamento esperado, não um bug).
4. Given o feed carregado, When aplico um filtro de período (data inicial/final), Then só vejo hunts iniciadas dentro do intervalo.
5. Given múltiplos filtros aplicados ao mesmo tempo, When combinados, Then o resultado respeita todos simultaneamente (AND, não OR).
6. Given múltiplos filtros aplicados, When o resultado é vazio, Then mostra mensagem clara "nenhuma hunt encontrada com esses filtros" — sem erro.
7. Given o feed carregado, When escolho uma ordenação (mais recente / maior profit por hora / maior XP por hora), Then a lista reordena de acordo.

## Complexity
T-shirt size: **S** — filtros e ordenação client-side sobre os dados já carregados do feed (Story 2.3); só precisa de 1 ajuste na view pra suportar filtro de monstro por completo (não só o "top 3").

## Business Value
Fecha o Epic 2 — sem isso, o feed vira ilegível assim que tiver mais que umas poucas hunts.

## Risks
- **Filtro de monstro só olhando o "top 3" exibido** perderia hunts onde o monstro apareceu mas não é um dos 3 mais mortos — mitigado adicionando um campo separado na view com a lista completa de monstros da sessão, usado só para filtrar (não exibido).

## Dev Notes

**Contexto (Story 2.3):**
- `useHuntsFeed.js` já busca todos os registros de `public_hunts_feed` de uma vez (sem paginação) — filtros e ordenação podem ser 100% client-side sobre esse array, sem novas queries ao Supabase. Simples e suficiente pro volume esperado do MVP.
- `top_monsters` (Story 2.3) é uma string formatada só pra exibição, limitada a 3 — **não usar pra filtro** (é isso que motiva o novo campo `all_monster_names`).
- Vocações possíveis (já usadas na Story 2.2): Knight, Elite Knight, Paladin, Royal Paladin, Druid, Elder Druid, Sorcerer, Master Sorcerer.
