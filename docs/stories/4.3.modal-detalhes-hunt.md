## Story
**As a** usuário,
**I want** clicar em qualquer card de hunt (própria ou compartilhada) e ver um modal com o resumo completo e os monstros mortos (com imagem, HP, XP e loot conhecido),
**so that** eu explore os detalhes de uma hunt sem sair da listagem, com dados reais de bestiário.

## Acceptance Criteria
1. Given qualquer `HuntCard` (própria ou compartilhada), When clicado, Then abre um modal/overlay com o resumo completo da hunt (duração, XP/h, profit/h, total), sem navegar para uma nova URL.
2. Given a lista de monstros mortos na hunt, When o modal exibe cada um, Then mostra imagem, HP e XP quando a criatura é encontrada na TibiaData (via `useCreature`/Story 4.1), e mostra só o nome + quantidade (sem quebrar) quando não é encontrada.
3. Given o usuário expande um monstro específico no modal, When expandido, Then exibe o `loot_list` conhecido daquela criatura (dado estático da TibiaData, não o loot real da hunt).
4. Given o modal aberto, When o usuário fecha (X, clique fora do conteúdo, ou Esc), Then o modal fecha sem side-effects; reabrir a mesma hunt não deve exigir novo carregamento de `session_monsters`/`session_items` no mesmo ciclo de vida do componente pai (mesmo padrão de cache local já usado em `SessionDetails`, agora dentro do modal).

## Complexity
T-shirt size: **M** — 1 componente `Modal` genérico novo, 1 `HuntDetailModal`, integração com `HuntCard` nas duas telas.

## Business Value
Fecha o Epic 4: entrega o valor central pedido pelo usuário — ver os monstros de uma hunt com imagem/detalhes reais, num fluxo de clique único a partir do card.

## Risks
- **Botão dentro de botão:** `HuntCard` com `onClick` não pode envolver o `footer` (toggle de compartilhamento em `SessionList`) dentro do próprio elemento clicável — HTML inválido (`<button>` aninhado). Mitigado nesta story: `HuntCard` isola a área clicável (título + stats + monstros) num `<button>` interno, com `footer` como irmão fora dele.
- **Fechar/reabrir gerando re-fetch:** mitigado mantendo o estado de "hunt selecionada" no componente pai (`SessionList`/`HuntsFeed`) e montando `HuntDetailModal` só quando há seleção — igual ao padrão de `mountedIds` do `SessionDetails` antigo, simplificado porque só uma hunt é exibida por vez.

## Dev Notes

**Contexto:**
- `SessionDetails` (removido na Story 4.2) já tinha a query exata de `session_monsters`/`session_items` por `session_id` — reaproveitada aqui dentro de `HuntDetailModal`.
- Não existe nenhum componente de modal no design system atual (`src/components/ui/`) — `Modal.jsx` é a primeira peça desse tipo, deve seguir o mesmo padrão visual (`bg-surface`, `border-border`, `rounded-xl`) dos demais componentes `ui/`.
- `HuntsFeed` não tem hoje nenhuma noção de "detalhe expandido" — o modal é a primeira vez que uma hunt compartilhada tem uma visão detalhada.

**Fora de escopo:**
- Deep-link/URL por hunt (decisão da Story: modal, não rota — ver epic).
- Loot real da hunt (o que a `session_items` já mostra) misturado com loot conhecido da criatura — ficam em seções visualmente separadas no modal pra não confundir "o que a criatura pode dropar" com "o que essa hunt específica lootou".

### Testing
- Clicar num card próprio (Dashboard) e num card compartilhado (Hunts Compartilhadas) → modal abre com os dados certos.
- Testar com uma hunt que tenha "Demon" registrado → imagem, HP 8200, XP 6000 visíveis; expandir → loot_list aparece.
- Testar com um monstro não encontrado na API → nome + quantidade aparecem, sem crash.
- Fechar via X, clique fora e Esc — todos devem funcionar.
- Confirmar que o botão de compartilhar/privar (`SessionList`) continua clicável independente do modal (não é filho do botão do card).
